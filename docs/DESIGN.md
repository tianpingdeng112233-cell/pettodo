## Problem Statement

ADHD 倾向 + 养宠物的用户（首个具体样本：David 本人 + codex 朋友）用效率型 todo 工具（苹果提醒事项/Todoist 类）坚持不下来。痛点不是缺功能，是缺「回来的理由」——ADHD 大脑靠即时情感反馈启动，传统 todo 给不了。

产品：手机端陪伴型习惯养成 app。用户上传自家宠物照片生成风格化形象（或从库中选），完成自设任务来「养」这只宠物。

## Demand Evidence

- **唯一行为证据**：David 给朋友在 codex 终端做了一个宠物陪伴，朋友「非常好」评价之后**数周仍在持续玩**（超过新鲜期，n=1，开发者）。
- 该朋友同为 ADHD + 养宠画像；David 本人即目标用户（ADHD 倾向、养宠物、todo 弃用史）。
- 品类级验证（二手）：Finch 是品类王者且 ADHD 社群是其最铁基盘；r/ADHD 反复安利。
- 缺口：尚无「自家宠物形象 × 养成循环」的产品；尚未与 3 个以上圈外真人聊过。

## Status Quo

目标用户在用苹果提醒事项/Todoist 类效率工具，几天后弃用；部分用 Finch 类养成 app（对这群人「自家宠物」差异点最直接可测，但情感迁移成本高）。真对手是「下载了但吃灰的 todo app」。

## Target User & Narrowest Wedge

- **人**：ADHD 倾向 + 养宠物 + 手机里躺着弃用 todo app 的人。第一批：David 本人 + codex 朋友。
- **最窄切口**：3 个日常任务 + 一只会为你开心的宠物形象（自家照片生成 vs 库选通用，是待验证变量而非既定卖点，见前提 2）。

## Constraints

- Solo 技术创始人，主业 MeetPR，此项目吃并行带宽。
- iOS first（复用 MeetPR 全套工具链：SwiftUI/TestFlight/签名/Codex 流水线）。
- 照片合规如实口径：MVP 阶段宠物照片经私人渠道（微信等）线下收取、人工出图，属小范围知情同意场景，**不是**「纯本地=合规已规避」；规模化 pipeline 阶段再做正式合规（个人信息、生图备案）。

## Premises

1. **【战场】** 情感陪伴型习惯养成产品，不是 todo 工具。北极星 = 第二周留存，不是任务吞吐。
2. **【差异点·假设】**「情感移植」——用户对自家宠物的现成感情移植进习惯回路（vs Finch 从零养感情）。**经 Codex 冷读降级为待验证假设**：真宠物形象可能有恐怖谷/情感不适风险。验证分两级：MVP v1 用**定性红灯**（任何「看到形象产生内疚/别扭/不适」的反馈即亮灯），定量 A/B 对照（自家 vs 库形象的留存差）**延后**到有量的 pipeline 阶段——n=5-10 分组在统计上测不出东西。形象生成技术已商品化（Adobe Firefly 等现成工具即可做），零壁垒；壁垒只能来自「自家宠物形象 × 养成循环 × ADHD-safe 设计」交集的整合深度。
3. **【红线】** 宠物永不因用户失败而受伤。断更不掉血、不蓬头垢面、无情感勒索。只做正向：完成 → 宠物开心/长大/解锁互动。未完成 → 任务静默顺延。
4. **【验证路径】** 第一裁判 = David + codex 朋友。先做两人真会每天打开的版本，真实留存说话，再谈扩张。不先建平台。

## Cross-Model Perspective

Codex（gpt-5.6-sol，独立冷读，未见对话）：

- **钢印**：ADHD-safe 情感陪伴产品，借用户对自家宠物的现成感情让「回来」本身成为奖励；任务只是解锁与宠物互动时刻的入口——无 streak、无惩罚、无内疚。
- **最有信息量的证据**：「朋友数周后还在持续玩」是全场唯一行为证据。先在手机上复刻 terminal 宠物的回访仪式，搞清朋友到底为什么回来，把那个循环原样保住，再谈效率功能。
- **挑战的前提**：情感移植最脆弱——真宠物形象即使永不受伤也可能加重内疚或有恐怖谷感。（已采纳，前提 2 降级为假设，验证机制见前提 2。）
- **48h 原型骨架**（细化后收编进下方 MVP Spec；「48h」仅为 Codex 原话，不作为工期承诺，实际口径见 Approach A）：SwiftUI+SwiftData+TestFlight；onboarding=照片+名字+3 任务；形象 concierge 人肉出素材，不建图像 pipeline；完成→即时动画+亲昵互动+朝解锁装饰推进；失败→静默顺延；每天一条宠物口吻邀请式通知。跳过：账号、社交、订阅、复杂任务管理、AI 聊天、自动生成、后端。

## MVP Spec（v1）

- **任务模型**：每人 3 个每日循环任务（文案自定，无优先级/子任务/截止时刻）。可随时改文案，不可超过 3 个。
- **顺延语义**：当日未完成的任务次日照常出现，无任何「昨日未完成」标记或提示——每天都是干净的一天。
- **反馈环**：完成任一任务 → 宠物即时动画（开心/扑跳）；当日 3/3 → 特殊亲昵互动；累计完成数推进解锁进度（首版曲线拍脑袋：累计 5/15/30 次解锁 3 个装饰，验证期数值不重要）。
- **通知**：每天固定时段一条宠物口吻邀请式本地通知；权限被拒 → 不降级、不再请求，app 内不出红点（红线延伸：不制造压力）。
- **形象素材**：每用户 3 张一致风格素材（待机/庆祝/睡觉），David 用现成风格化工具（Adobe Firefly 类，注意免费档有 credit 限额，10 人×3 图×重试量级需现场核实够不够）人肉出图。**投递机制 = 所有种子用户（≤10 人）的素材包全部打进同一个 build，onboarding 时选自己**——一次代码改动只打一个包，避免 per-user build 的重打包倍增和 tester 分组麻烦；不上远程下载，避免引入后端。此为已知工程项，不是零成本。
- **留存度量（无后端方案）**：SwiftData 本地记录打开/完成/通知点击事件（本地通知只能测点击，「送达但被无视」测不了，n≤10 无所谓）；设置页内置「导出数据」按钮（分享 JSON 给 David 微信）；配合每周一次人肉问卷。不上埋点 SDK，不建收集端点。
- **明确不做**：账号、社交、订阅、后端、自动生成、AI 聊天、iPad、安卓、widget（C 方案延后）。

## Approaches Considered

### Approach A: Concierge MVP（已选）
- 纯本地 SwiftUI+SwiftData，无后端；形象人肉 concierge 出素材随 build 内置；3 任务正向反馈环；TestFlight 分发。
- Effort: human ~2 周 / CC+Codex ~2-3 天（已砍对照臂后的口径）；Risk: Low。
- 复用 MeetPR 全套 iOS 工具链，两周内开始回答「第二周还有人打开吗」。
- 短板：人肉形象不可规模化，验证成功后补 pipeline；per-user 打包在种子超过 ~10 人后不可持续。

### Approach B: 完整产品线（否决）
- 自动生图 pipeline + 后端 + 账号 + 订阅，Effort XL，违反前提 4——为幻影用户写三个月代码；生图成本/风控/境内合规提前暴露。

### Approach C: 宠物住在桌面 widget-first（延后采纳）
- 宠物主体住 iOS 桌面小组件/锁屏，物理删除「记得打开 app」这个 ADHD 最大故障点；每天几十次解锁 = 免费曝光。
- Effort M；widget 受系统限制（时间线刷新预算 timeline refresh budget、交互深度受限），动画表现力打折。
- **定位：A 验证出基础留存后的第一个追加项**（作为留存优化手段此时才测得出增量）。

## Recommended Approach

**A（Concierge MVP），C 作为验证成功后的第一追加项。**验证问题只有一个：「看到并逗乐我家宠物，会不会让我明天再打开？」前提 2 在 v1 用定性红灯监测，定量对照延后。

## Validation Phases

- **Phase 1（v1，~2 周内）**：David + codex 朋友两人，目标 = 第 14 天双双仍在打开。任何一人流失即复盘循环设计。
- **Phase 2（Phase 1 通过后）**：扩至 5-10 个种子（各自认识的养宠朋友），继续用导出+问卷度量；此阶段开始收集「库选形象」意愿信号，为 pipeline 阶段的定量对照铺路。

## Open Questions

1. codex 朋友持续玩的到底是什么循环（陪伴感？打断彩蛋？完成反馈？）——尚未拆解，直接决定 mobile 复刻什么。
2. 宠物已过世用户的情感边界（做还是明确不做，onboarding 如何措辞）。
3. 多宠物家庭选哪只 / 照片质量不足以出图时的 onboarding 措辞（concierge 阶段 David 人肉兜底，规模化前须产品化）。
4. 商业化完全未讨论（Finch 订阅制可参考，但在留存验证前不配讨论）。
5. 与 MeetPR 的带宽冲突如何排——本项目的时间盒是什么。

## Success Criteria

- **Phase 1 主指标**：第 14 天 David 与朋友双双仍在打开（数据来自本地记录导出）。
- **Phase 2 主指标**：5-10 人种子池的第 14 天打开比例，**通过线 ≥ 半数**（低于半数 = 循环设计回炉，不进 pipeline 阶段）。
- **反指标（前提 2 红灯）**：出现任何「因宠物形象产生内疚/恐怖谷/不适」的反馈。

## Distribution Plan

- MVP：TestFlight 内测（复用 MeetPR 的 ASC 账号与流程），单一 build 内置全部种子素材包。
- 正式分发（验证后）：App Store；境内合规（照片个人信息、生图备案）在 pipeline 阶段处理。
- CI：起步无需；进 repo 后套用 MeetPR 的 GitHub Actions 模板。

## Dependencies

- 已知工程项：per-user 素材打包流程；本地事件记录+导出。无外部技术阻塞。
- 人肉形象需选定一个风格化工具（Adobe Firefly 类，MVP 阶段手工）。
- 真正的依赖是 David 的并行带宽（MeetPR 为主线）。

## The Assignment

**本周内做两件事，都不是写代码：**
1. 问 codex 朋友三个问题：那个宠物你现在还每天看吗？它对你来说到底是什么（陪伴/彩蛋/仪式）？手机上有一个这样的宠物帮你管 3 件日常事，你会每天打开吗？
2. 各自找 2-3 个「ADHD 倾向 + 养宠」的朋友（为 Phase 2 凑 5-10 人种子池），只问一句：「如果完成任务能让你家猫/狗的卡通形象开心起来，你会试吗？」记录原话。

## What I noticed about how you think

- 被问「最硬的证据」时，你没有拿赛道数据糊弄，给的是一个具体的人和一段真实经历——「我帮朋友 codex 端做了一个宠物，他觉得非常好」。证据意识是对的。
- 追问后你说「还在持续玩」——你知道持续行为和一次性夸奖的区别，没有把客套话当需求。
- 「ADHD 并且养宠物的用户」被拷到「说出能发微信的人」时，你的回答是「我自己就是，我朋友也是」——founder-market fit 不是包装出来的，是本来就在那。
- 四条前提你一次全认，但 Codex 挑战情感移植时你选择降级为假设而不是嘴硬——愿意让数据裁决自己最得意的洞察，这比洞察本身更稀缺。
